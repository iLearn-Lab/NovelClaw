# 工作台优化说明

这轮修改覆盖启动部署、生成任务、数据保存、实时页面和自动化验证。

## 已处理的问题

- 本地一键启动保留已有配置；后台启动服务并检查健康状态，启动失败时给出日志位置。
- Docker 复用依赖安装层和公共镜像，等待入口服务就绪，并持久化故事记忆目录。
- 同一任务只能被一个执行器领取；已取消、失败或完成的任务不会因重复请求重新启动。
- 取消与任务完成同时发生时保留取消状态；取消、超时和监控异常都会清理子进程。
- 日志只读取需要显示的末尾片段，子进程输出直接写入文件，减少内存占用和数据库查询。
- 稿件与记忆采用原子写入，写入失败不会截断已有文件；多个记忆写入者会合并不同条目和字段的修改。
- 编辑章节时检测旧版本冲突，返回明确提示并保留输入；无效 JSON 请求返回 400。
- 修复生成流程中人物分支引用未定义变量的问题，补全角色分工和中英文提示，移除不可达旧代码。
- 修复 MCP 页面乱码和模板错误，统一主导航品牌名称。
- 实时刷新改为串行请求，断网后逐步重试，后台标签页暂停刷新，结束的任务停止轮询。
- 发送失败保留写作输入；避免没有变化时重复重建运行界面，也不再自动打断向上阅读。
- 手机端使用可收起导航，把对话和输入区放在前面；支持键盘跳转、焦点提示、Escape 关闭导航和减少动画偏好。
- 补充跨平台 Python 测试、JavaScript 轮询测试、浏览器检查和 GitHub Actions。

## 验证与限制

验证步骤见 [开发指南](DEVELOPMENT.md)。测试使用临时数据库、虚拟模型结果和
隔离的浏览器会话，不会调用收费模型。真实模型生成的质量和可用性仍需结合
自己的服务商进行验证。

记忆库能够合并不同内容的并发修改；同一字段同时修改时以后写入的值为准。
章节编辑则通过版本冲突提示防止静默覆盖。当前公开版仍使用共享预览用户，
本轮没有将其改造成多租户账号系统。

本机浏览器验证使用 Chrome；Docker 构建需要有 Docker 的环境，CI 中包含
Compose 配置检查。自定义记忆存储目录需要配置对应的数据卷。

本机验证结果：71 项 Python 测试通过，49 个不适用于对应服务的组合跳过；
4 项 JavaScript 轮询测试通过，Python 静态检查与 JavaScript 语法检查通过。
三个服务的 Chrome 浏览器检查、手机导航与失败提交保留输入检查通过；
Windows 启动脚本已实际启动三个服务并验证健康状态，测试服务随后已关闭。
